# ❄️ Кондей-Мастер

Приложение для мастера по установке кондиционеров: финансы («Анти-долг»), CRM заказов, календарь занятости, складской учёт и ИИ-ассистент для общения с клиентами.

## Модули

1. **Финансы «Анти-долг»** — прогресс-бар цели (1 200 000 ₽), быстрый ввод доходов (установка / Яндекс.Доставка) и расходов, рекомендация суммы для досрочного погашения (60% чистой прибыли за неделю).
2. **Заказы (CRM)** — карточки заказов (клиент, адрес, модель, трасса, цена), статусы «Новый → В работе → Завершён». При завершении заказа материалы автоматически списываются со склада, а стоимость работы падает в доходы.
3. **Календарь** — блокировка дней («Основная работа», «Выходной», «Заболел»), заказы отмечаются на календаре. ИИ не предлагает клиентам занятые дни.
4. **Склад** — остатки материалов (труба, кабель, кронштейны, анкера и т.д.), алерты при низком остатке.
5. **ИИ-ассистент (AI Router)** — общение с клиентами. Провайдер переключается в настройках: OpenRouter (DeepSeek), YandexGPT, OpenAI, локальный ПК (Ollama/LM Studio). **Fallback:** если ИИ недоступен, диалог автоматически переводится в «Ручной режим» и приходит уведомление.
6. **Чаты** — единое окно диалогов, тумблер «ИИ отвечает / Ручной режим», ручные ответы из админки, тестовый режим (симуляция клиента).

## Запуск на сервере (Docker — рекомендуется)

```bash
git clone <repo> kondei && cd kondei
cp .env.example .env      # задай ADMIN_PASSWORD (пароль входа в админку)
docker compose up -d --build
```

Приложение поднимется на `127.0.0.1:8080` (только localhost — наружу его выставляет твой nginx). Пример блока для nginx на хосте:

```nginx
server {
    listen 443 ssl;
    server_name kondei.твой-домен.ру;
    # ssl_certificate ... (certbot)

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }
}
```

База SQLite хранится в docker-томе `kondei-data` и переживает пересборки. Обновление: `git pull && docker compose up -d --build`.

Вход защищён паролем `ADMIN_PASSWORD` (сессия-cookie на 30 дней). Если переменная пустая, вход отключён — так работает только локальная разработка.

## Запуск локально (для разработки)

```bash
# Backend
cd backend
npm install
cp .env.example .env
npm run db:push     # создать БД (SQLite)
npm run db:seed     # начальные остатки склада
npm run dev         # http://localhost:3001

# Frontend (в другом терминале)
cd frontend
npm install
npm run dev         # http://localhost:5173
```

## Настройка ИИ

Вкладка «⚙️ Настройки» → выбрать провайдера → вписать API-ключ → «Проверить ИИ».

- **OpenRouter**: ключ с openrouter.ai, модель например `deepseek/deepseek-chat`.
- **YandexGPT**: ключ в формате `folderId:apiKey`, модель `yandexgpt-lite`.
- **OpenAI**: обычный API-ключ, модель `gpt-4o-mini`.
- **Локальный ПК**: URL Ollama (например `http://192.168.1.10:11434`), модель например `qwen2.5:7b`.

## Мессенджеры (WhatsApp / Telegram / MAX)

Коннекторы заложены как подключаемые модули в `backend/src/messengers/index.ts`. Входящие сообщения передаются в `POST /api/chats/incoming` — ИИ отвечает автоматически (или диалог уходит в ручной режим).

⚠️ **Важно:** userbot-режимы на личных номерах нарушают правила WhatsApp/Telegram — есть риск блокировки номера. Безопаснее начать с официального Telegram-бота.

## Переход на Supabase (PostgreSQL)

1. В `backend/prisma/schema.prisma` замените `provider = "sqlite"` на `provider = "postgresql"`.
2. В `backend/.env` укажите `DATABASE_URL` из Supabase (Settings → Database → Connection string).
3. `npm run db:push && npm run db:seed`.

## Telegram Mini App

Фронтенд — обычное SPA, готовое к упаковке в TMA: задеплойте frontend на любой HTTPS-хостинг и укажите URL в BotFather (`/newapp`).
